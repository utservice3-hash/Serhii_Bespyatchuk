# METRICS_GLOSSARY — єдиний стандарт назв показників

> **Правило №1:** одна суть = ОДНА назва в усіх розділах. Різна логіка = РІЗНІ назви
> (однакова назва ніколи не сміє показувати різні числа). Будь-який новий показник
> звіряється з цим файлом ПЕРЕД додаванням.
> Розділи: Огляд (overview) · Звіт (report) · Звіт КВП (kvp) · Команди (teams) ·
> Плани (plans) · Статистики-відділи (depstats) · Задачник (tasks).

## 1. Гроші

| Стандартна назва | Логіка (джерело числа) | Де є |
|---|---|---|
| **Отримані кошти** | «Успішно реалізовано» (статус 142, за `closed_at_kommo` у періоді) + «Оплата отримана» (снапшот статусів 69716460/60412544, без дати). Пайплайни 8921932+155304. | Огляд, Звіт, КВП, Команди (було «Виручка»), Плани («Факт») |
| **Успішно реалізовано** | SUM(price) угод 142, закритих у періоді. | Звіт, КВП (було «Дохід успішно закритих угод»), Статистики `revenue_won` (було «Дохід успішно закритих») |
| **Оплата отримана (знімок)** | SUM(price) угод ЗАРАЗ на 69716460/60412544. Транзитний етап → знімок, без дати. | Звіт, КВП, Статистики `payment_received` |
| **Очікувані оплати** | SUM(price) угод ЗАРАЗ на етапі `invoiced` («Виставлено рахунок»), знімок. | Огляд, Звіт (було «Очікування оплати»), КВП, Плани («Очікувані»), Статистики `invoiced_amount` (було «Вислані рахунки») |
| **Виручка від нових клієнтів** | Отримані кошти клієнтів, чия ПЕРША оплата lifetime — у періоді. | Огляд, КВП (було «…(РНК)» — суфікс прибрано: це тип клієнта, не команда) |
| **Виручка від постійних клієнтів** | Отримані кошти клієнтів із 2+ оплатами lifetime. | Огляд, КВП (було «…(РПК)») |
| **Успішні угоди готівкою** | SUM ПРИХОДУ (поле «Розрахунок приходів», НЕ бюджет!) готівкових 142-угод, закритих у періоді. | Статистики `cash_deals_amount` |
| **Перенесено з мин. міс.** | Знімок угод «у роботі» на 1-ше число (`monthly_carryover`). | Огляд, Звіт, КВП |
| **Дебіторка** | SUM(`receivables.amount`) — файл дебіторки + готівкові з CRM. Знімок. | Огляд, Звіт, КВП, Команди, Статистики-фінанси `receivables` |

## 2. Кількості (угоди/машини/люди)

| Стандартна назва | Логіка | Де є |
|---|---|---|
| **Кількість успішних угод (авто)** | COUNT угод 142, закритих у періоді (з 2026: 1 угода ≈ 1 машина). | КВП (було «Кількість успішних угод»), Статистики `machines_success` (було «Кількість успішних авто») |
| **Поставлені машини** | Снапшот-проксі: угоди повного циклу, СТВОРЕНІ в періоді, що ЗАРАЗ на `invoiced`/`paid` АБО стадіях АВТО (69716300/98470988/10937178). | Звіт (було «Відправлено авто»), КВП, Статистики `machines_dispatched` |
| **Поставлені авто (за подіями)** ⚠️ інша логіка | Події ВХОДУ в «Авто працює» за день (`deal_stage_events`). Рішення власника: задачник рахує саме події дня. | Задачник `dispatch_count` |
| **Створені угоди (повний цикл)** | COUNT угод 8921932+155304 за `created_at_kommo` у періоді. | Огляд, Звіт, КВП |
| **Оплата отримана, шт (знімок)** | COUNT угод зараз на 69716460/60412544. | КВП |
| **Нові клієнти** | Клієнти, чия перша оплата lifetime — у періоді. | Огляд, Звіт, КВП |
| **Постійні клієнти** | 2+ оплат lifetime ТА активні (вікно `sleepingWindowMonths`). | Огляд, Звіт, КВП, Статистики-логістика `repeat_clients_active` |
| **Менеджерів у продажу** | COUNT активних менеджерів команд продажу. | КВП, Статистики `managers_count` |
| **Кількість дзвінків** | Ringostat live: `employee_fio`→менеджер→тімлід, результативні = `billsec>0`. | Статистики `calls` |

## 3. Середні чеки — ⚠️ ДВІ РІЗНІ ФОРМУЛИ (тому різні назви!)

| Назва | Формула | Де є |
|---|---|---|
| **Середній чек** | Отримані кошти ÷ к-ть угод (у «отриманих»). | Огляд, Звіт, КВП, Команди |
| **Середній чек (успішні)** | Успішно реалізовано ÷ успішні угоди. Так рахував лист. | Статистики `avg_check` (sales) |
| **Сер. чек на поставлену** | Успішно реалізовано ÷ поставлені машини. Легасі листа. | Статистики `avg_check_income` |
| **Середній чек (постійні)** | Виручка постійних ÷ машини постійних. | Статистики-логістика `avg_check` |

## 4. Реклама / лідоген

| Стандартна назва | Логіка | Де є |
|---|---|---|
| **Прийнято реклами (CRM)** | Угоди повного циклу, створені в періоді: `client_source ∈ adSources` АБО `lead_channel='ad'`, НЕ реактивація (`adDealSql`). | Звіт («Прийнято реклами»), КВП (було «К-ть лідів з реклами (CRM)»), Задачник `ads_count` |
| **Ліди з реклами (з листа)** ⚠️ інше джерело | Історичні числа ручного листа (~1200/міс) — НЕ відтворюються з CRM (звірка: Кваліфікація-всі ±29% нестабільно, ад-джерело −87%). Ймовірно GA/кабінет. ЧЕКАЄ визначення власника → тоді auto. | Статистики `ad_leads` (було «Реклама: кількість лідів») |
| **Заявки з реклами (GA)** | `ad_budget_daily.conversions` (Google-таблиця реклами). | КВП |
| **Рекламний бюджет** | `ad_budget_daily.budget_fact`. | КВП, Статистики `ad_budget_total` |
| **К-ть не цільових лідів** | Кваліфікація 8921928, статус 143, створені в періоді. | КВП, Статистики `non_target_leads` |
| **Передані заявки** | Реєстр лідоген-бота (`leadgen_registry`), distinct lead_id за період. | Огляд, Звіт («Передані заявки (лідоген)»), КВП |
| **Конверсія лідогену** | Передані заявки, чий клієнт дійшов до оплати ÷ передані. | Огляд, КВП |
| **Конверсія прорахунок→новий** ⚠️ інша формула | Нові клієнти ÷ прорахунки (формула листа). | Статистики-лідоген `conversion` (було просто «Конверсія») |
| **Конверсія реклами** | Оплачені з реклами ÷ ліди з реклами. | Огляд, КВП, Статистики `ad_conversion` |
| **Озвучено ціну в перший дотик** | AI-транскрибація дзвінка (лист «Перший дотик» → `first_touch_analysis`), `price_voiced=так`. | Звіт |

## 5. Відкриті рішення власника (формули НЕ уніфіковані свідомо)

1. **Середній чек**: Звіт/Огляд ділять «отримані кошти» на всі угоди; Статистики (як лист) — «успішно» на успішні. Уніфікувати? Зміняться числа в одному з місць. Поки що — різні назви (§3).
2. **Поставлені авто в Задачнику** — за подіями дня (рішення власника 07.2026), відрізняється від снапшот-проксі. Лишаємо, назва «(за подіями)».
3. **Ліди з реклами (з листа)** — джерело листа невідоме (ймовірно GA-конверсії ≈ `ad_budget_daily.conversions`, порядок збігається: липень 598 за півмісяця ≈ 1300/міс vs лист ~1200). Підтвердить власник → перемкнемо на auto.
