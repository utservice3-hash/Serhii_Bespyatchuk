# Інфраструктура та готові рішення — UTS Dashboard

Що будувати самим, а що взяти готовим. Плюс дорожня карта узгоджених доробок.

---

## 1. Принцип: custom-логіка — своя, «загальне» — готове

| Потреба | Рішення | Чому |
|---|---|---|
| **Бізнес-логіка** (воронка, гроші, мінус-угоди, передані заявки, задачі, план/факт) | **Наш застосунок** | Жоден готовий BI не знає ваших правил (статуси Kommo, знімки оплат, РПК-воронка). Це ядро цінності. |
| **Ad-hoc аналітика, довільні графіки** | **Metabase** поверх того ж Postgres | Будь-хто кліками будує звіти без коду. Заміна Google Data Studio, але на живих даних. |
| **Бекапи** | Neon PITR + наш нічний CSV-дамп | Див. `BACKUP_RECOVERY.md`. Не пишемо своє сховище. |
| **Моніторинг аптайму** | **UptimeRobot** (безкоштовно) на `/api/health` | Пінгує щохвилини, шле алерт у Telegram/пошту, якщо впало. |
| **Сповіщення** | наш бекенд + **grammy** (вже є) у Telegram | Логіку знаємо ми; доставку робить Telegram. |

## 2. Metabase — ad-hoc аналітика (рекомендую)

**Що дає:** керівник/аналітик відкриває веб, кликами будує таблиці/графіки/дашборди по будь-яких полях, зберігає, шарить. Без звернень до розробника.

**Як підняти (≈1 год):**
1. Розгорнути Metabase (Docker: `metabase/metabase`, або хмара metabase.com).
2. Підключити **той самий Neon Postgres** — але **окремим read-only користувачем** (щоб аналітики не могли нічого змінити):
   ```sql
   CREATE ROLE metabase_ro LOGIN PASSWORD '…';
   GRANT CONNECT ON DATABASE neondb TO metabase_ro;
   GRANT USAGE ON SCHEMA public TO metabase_ro;
   GRANT SELECT ON ALL TABLES IN SCHEMA public TO metabase_ro;
   ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO metabase_ro;
   ```
3. Готово — таблиці видно, будуються звіти.

**Межа:** Metabase бачить **сирі таблиці**, не наші «розумні» метрики (мінус-угоди, знімки оплат). Для складних правил — лишається наш дашборд. Metabase = «покопатись у даних», наш застосунок = «правильні бізнес-показники».

## 5. Пропозиції по Telegram-сповіщеннях (на обговорення)

Зараз ТГ уже є (сповіщення про передані заявки). Пропоную додати **адресні, дієві** тригери:

**Щоденні (ранкові дайджести):**
- **Тімліду о 08:30:** підсумок вчора по команді (оплати ₴, прорахунки, авто) + хто 0 активності 2+ дні.
- **Менеджеру о 09:00:** його план на сьогодні + відкриті задачі з дедлайном сьогодні.

**Подієві (миттєві):**
- 🔴 **Синк впав** (`consecutiveFailures ≥ 3`) → адміну.
- 💰 **Велика оплата** отримана (> порогу) → тімліду (мотивація).
- ⏰ **Боржник прострочив** понад ліміт → відповідальному менеджеру + тімліду.
- 🐢 **Угода застрягла** на етапі > N днів → менеджеру.
- 📉 **План відстає** від темпу (у середині місяця виконання < очікуваного %) → тімліду.

**Тижневі:**
- **Пн 09:00:** підсумок минулого тижня по кожному менеджеру (для наради).
- **Чт 09:00:** темп поточного тижня.

Механіка: ті самі cron-джоби в бекенді + grammy. Пороги — у `app_settings` (редагуються в Налаштуваннях). Скажи, які тригери вмикаємо — зроблю.

## 6. Поточний стек (для нового розробника/асистента)

- **БД:** Neon Postgres. Структура — `backend/src/db/schema.sql`. Мапінг етапів — `seedKommoMapping.sql`.
- **Деплой:** relay-PHP на сервері evraziat (див. `CLAUDE.md`). Прод тягне гілку `claude/friendly-galileo-8pijhl`.
- **Джоби:** синк Kommo (5хв), події етапів (10хв), передані заявки (10хв), дебіторка (30хв), новини (08:00), KPI-задачі (07:00), реконсиляція (04:00), **бекап (03:00)**.
- **Проєктна памʼять:** `CLAUDE.md` — тримати актуальним (усі бізнес-правила там).
