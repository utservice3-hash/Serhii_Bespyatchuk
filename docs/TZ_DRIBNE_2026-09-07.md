### B · Прослуховування дзвінків у картці клієнта

**Власник (06:27–06:56):** «внизу … Рінгостат … це треба налаштувати, історію по дзвінках, щоб була … кожного клієнта, з яким зв'язується менеджер, може треба прослухати».

- **Гейти:** (а) дзвінки клієнта == дзвінки з `ringostat_calls` за тим самим ключем, одним викликом; (б) менеджер чужого клієнта → 403, свого → 200 (дзеркало).
- **Приймання:** відкрити картку клієнта з дзвінками за 30 дн — список збігається з числом у базі; клік «▶» відкриває запис.

### D · Новини: автоматична публікація змін дашборду

**Власник (16:50–17:44):** «усі зміни, які ти робиш глобальні … вкладка новини … публікується автоматично … можна було його і в групу новин у ТГ переносити».

- **Що є:** новини пишуться руками через `POST /news`. Ланцюг викату знає sha, час і список комітів (`foreignCommits`).
- **Що робити:** крок ланцюга (після `healthVersion`), який створює запис у `news` категорії `company`: заголовок «Оновлення дашборда · <дата>», тіло — людські підписи змін. **Джерело тексту — окреме поле для людей**, не сирі коміт-повідомлення (вони технічні). Найпростіше чесне: файл `RELEASE_NOTES.md` у корені, звідки крок бере верхній блок; порожній блок — новини немає (не публікувати «оновлено» без змісту).
- **Формат для ТГ:** тіло новини — простий текст із маркерами, придатний для копіювання в групу. Автопостинг у ТГ — **не в цьому проході**.
- **Чого НЕ робити:** не публікувати кожен `app_boot` (рестарти ≠ релізи), не дублювати при повторному викаті того ж sha (ідемпотентність по sha).
- **Гейти:** той самий sha двічі → одна новина; порожні нотатки → нуль новин (порожній результат тут — правильна поведінка, і це має бути названо в тесті); саботаж — прибрати перевірку sha → дубль.
- **Приймання:** після викату у вкладці «Новини» зʼявляється один запис із правильним текстом; повторний прогін кроку нічого не додає.
- **Питання власнику:** що вважати «глобальною зміною», гідною новини — кожен викат чи лише з видимими змінами?

- **Питання власнику:** тімлід **архівує** чи лише **бачить** архів? Без відповіді робити лише перегляд (`GET`).

### J · Новини: значок «99+» після викату (додано 08.09.2026)

**Скарга:** викотилась одна новина, а на значку «99+».

- **Причина (заміряно 08.09):** свіжа збірка бере мітку «долистав досюди» з `localStorage`
  (`readNewsSeenId`, `Dashboard.tsx:270`). Якщо мітки ще немає — повертає **0** і шле
  `sinceId=0`. Бекенд (`routes/news.ts /unread`) приймає 0 як справжнє число і рахує
  `id > 0` = **усі 200 живих новин** з червня. Фолбек на колонку акаунта `news_seen_at`
  не спрацьовує, бо 0 — «скінченне число». Це рівно клас «порожній скоуп не можна
  виражати нулем» (CLAUDE.md, правило 7).
- **Що робити:** відсутню мітку слати як «немає» (`undefined`), а не 0; на бекенді 0
  теж трактувати як «немає» і йти у фолбек по `news_seen_at`. Обидві половини, бо
  старий бандл у чиїйсь вкладці ще довго слатиме 0.
- **Гейт:** `/unread` без `sinceId` і з `sinceId=0` дають ОДНЕ число, що дорівнює
  лічильнику по `news_seen_at`; саботаж — прибрати трактування 0 → червоне.
- **Приймання:** користувач, що ніколи не відкривав «Новини» в новій збірці, бачить
