# Відпустки для тайм-трекера — контракт (задача 5149, етап 3)

Трекер сам питає дашборд, хто й коли у відпустці. Дашборд — єдине джерело відпусток («Календар команди»).
Код: `backend/src/routes/integrations.ts`, правило — `trackerVacations` у `backend/src/core/vacationRules.ts`,
гейти `#1807`/`#1807b` (`backend/src/routes/integrations.test.ts`).

## Запит

```
GET https://dashboard.uts.ua/api/integrations/tracker/vacations?from=2026-10-01&to=2026-10-31
X-Tracker-Vacations-Key: <ключ>
```

- Ходить **лише сервер трекера**; ключ живе тільки на сервері.
- Ключ окремий від SSO (`X-Dashboard-Sso-Key` тут не приймається) і дає лише читання відпусток.
- `from`, `to` — `YYYY-MM-DD`, обидва дні включно, `from ≤ to`, період не довший за 366 днів.

## Відповідь `200`

```json
{
  "vacations": [
    { "dashboardUserId": 8,  "email": "first@uts.ua",  "from": "2026-09-28", "until": "2026-10-02", "type": "vacation" },
    { "dashboardUserId": 9,  "email": "second@uts.ua", "from": "2026-10-12", "until": "2026-10-16", "type": "vacation" },
    { "dashboardUserId": 10, "email": "gone@uts.ua",   "from": "2026-10-20", "until": "2026-10-24", "type": "vacation" }
  ]
}
```

(Саме цей приклад звіряє гейт `#1807` на тестовій базі — розійдеться з кодом, гейт почервоніє.)

- Кожна **погоджена** відпустка, що перетинає період, з її **справжніми** датами — не обрізаними по `from`/`to`
  (перший рядок починається у вересні). Порядок — за датою початку, далі за `dashboardUserId`.
- `from`, `until` — календарні дати (київський день), обидва включно.
- `dashboardUserId` — id акаунта в дашборді, той самий, що в `GET /api/auth/tracker-users`. Зіставляти за ним;
  `email` — запасний ключ.
- `type` — зараз завжди `"vacation"`. Лікарняні, відгули й відпустки «на погодженні» не віддаються.
- Вимкнений акаунт віддається: відпустка була, і звіт за минулий період мусить показати її відпусткою.
- Відпустка людини без акаунта в дашборді не віддається — у трекері такої людини немає.
- Нема відпусток — `{ "vacations": [] }`.

## Помилки

| код | тіло | коли |
|---|---|---|
| `400` | `{ "error": "<причина>" }` | дати не `YYYY-MM-DD` / неіснуючі, `from` пізніше `to`, період > 366 днів |
| `401` | `{ "error": "bad_key" }` | ключа немає або він не той (зокрема SSO-ключ) |
| `503` | `{ "error": "not_configured" }` | на дашборді не налаштовано `TRACKER_VACATIONS_KEY` |

Будь-яка помилка чи тайм-аут — трекер працює як звичайно, просто без значка.
