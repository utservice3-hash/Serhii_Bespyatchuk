## 0. Одним абзацом

Дашборд стає єдиним місцем навчання замість «Середи». Кандидат отримує акаунт із роллю «Кандидат» і бачить лише вкладку «Навчання». Курс складається з блоків, блоки з уроків і тестів; наступне відкривається лише після попереднього; курс зараховано при 100 % і складеному екзамені. Керівник бачить зведення: хто на якому кроці, з якими балами, хто застряг. Після рішення про найм керівник однією дією обирає команду, і кандидат стає менеджером.

## 3. Ролі й доступ

| роль | що бачить у «Навчанні» | що може |
|---|---|---|
| **Кандидат** (нова, `candidate`) | лише курси з аудиторією `candidate`; жодної іншої вкладки | проходити уроки й тести |
| Менеджер | курси з аудиторією `manager` і `all` | проходити; послідовність **не блокує** (пропоную, питання 10.1) |
| Тімлід | те саме + зведення по **своїй команді** | переглядати прогрес своїх |
| КВП, опдир, СЕО, адмін | усі курси + зведення по всіх | адмін і опдир: редагувати курси, «Прийняти на роботу» |
| HR, бухгалтерія | як зараз (тумблер вкладки в Налаштуваннях) | — |

Технічно: роль `candidate` — рядок у `ROLE_DECLARATIONS` (інакше `#15` червоніє на прийманні, як із «Бухгалтерією» 04.09) + сід у `roles`: `screen_access = {training: true}`, `permissions = {}`, `data_scope = 'own'`. Редагування курсів — право `manage_training` (нове), за замовчуванням в адміна й опдира; можна ввімкнути Даші чи Юлі тумблером.

🔴 **Кандидат не є менеджером CRM**: `users.manager_id = NULL`. Усі місця, що припускають наявність менеджера у користувача (звіт, календар, задачник як виконавець), він не бачить за роллю, тож падіння немає. Перевірити гейтом C (розділ 8).

## 4. Модель даних

### 4.1 Нові таблиці

```
training_courses
  id            SERIAL PK
  title         TEXT NOT NULL
  description   TEXT
  audience      TEXT NOT NULL CHECK (audience IN ('candidate','manager','all'))
  sequential    BOOLEAN NOT NULL DEFAULT true     -- ② блокувати наступне
  position      INTEGER NOT NULL DEFAULT 0
  published     BOOLEAN NOT NULL DEFAULT false
  created_by    INTEGER REFERENCES users(id)
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()

training_progress
  id            SERIAL PK
  user_id       INTEGER NOT NULL REFERENCES users(id)
  material_id   INTEGER NOT NULL REFERENCES training_materials(id) ON DELETE CASCADE
  status        TEXT NOT NULL CHECK (status IN ('opened','done'))
  score         NUMERIC            -- для тестів: відсоток правильних, 0..100
  passed        BOOLEAN            -- для тестів: score >= pass_score
  attempts      INTEGER NOT NULL DEFAULT 0
  answers_json  JSONB              -- остання спроба, для розбору керівником
  opened_at     TIMESTAMPTZ NOT NULL DEFAULT now()
  finished_at   TIMESTAMPTZ
  UNIQUE (user_id, material_id)

training_events                    -- журнал: хто, що, коли (для «застряг» і для спорів)
  id, user_id, material_id, kind ('open','done','quiz_attempt','exam_unlock','hired'), payload_json, at
```

### 4.2 Зміни наявних таблиць (лише додавання колонок)

```
training_folders     + course_id INTEGER REFERENCES training_courses(id)   -- папка = блок курсу
training_materials   + kind дозволяє 'quiz'
                     + quiz_json JSONB        -- див. 4.3
                     + is_exam BOOLEAN NOT NULL DEFAULT false
                     + required BOOLEAN NOT NULL DEFAULT true   -- необовʼязковий урок не входить у 100 %
users                (нічого нового: role_override='candidate', manager_id NULL)
```

### 4.3 Форма тесту `quiz_json`

```json
{
  "pass_score": 80,
  "max_attempts": null,
  "shuffle": true,
  "questions": [
    { "id": "q1", "text": "…", "kind": "single", "options": ["…","…","…"], "correct": [1] },
    { "id": "q2", "text": "…", "kind": "multi",  "options": ["…","…"],     "correct": [0,1] },
    { "id": "q3", "text": "…", "kind": "text",   "correct": null }
  ]
}
```
- `single`/`multi` перевіряються автоматично; `text` (вільна відповідь) не рахується в бал, зберігається для керівника.
- Бал = правильні ÷ автоматичні × 100, округлення до цілого.
- Для екзамену `max_attempts = 3` за замовчуванням (пропоную, питання 10.2); після вичерпання керівник відкриває ще одну кнопкою.

### 4.4 Бекфіл
Один курс «Загальне навчання» (`audience='all'`, `sequential=false`), усі наявні папки отримують його `course_id`. Один `UPDATE`, оборотний. Після нього кожен матеріал належить курсу — гейт F.

## 5. Правила прогресу — нормативно

1. **Одиниця прогресу** — матеріал із `required=true` (урок або тест).
2. **Урок done**: натиснута кнопка «Пройшов» після відкриття; для відео додатково `≥ 90 %` перегляду не вимагаємо (embed не віддає позицію надійно).
3. **Тест done**: `passed=true`.
4. **Відсоток курсу** = done ÷ усіх required матеріалів курсу × 100, ціле. Екзамен входить у знаменник.
5. **Доступність матеріалу** при `sequential=true`: усі попередні за порядком (блок за `position`, усередині блоку матеріал за `position`) done. Інакше відповідь `423 Locked` з `{ blockedBy: {materialId, title} }` — фронт показує «спершу пройди: …».
6. **Екзамен** (`is_exam=true`) доступний, коли усі інші required done. Він завжди останній у курсі за побудовою (редактор не дає поставити його вище).
7. **Курс зараховано** = 100 % і екзамен passed. Пишеться подія `course_done`.
8. **Застряг** = курс не зараховано і немає подій ≥ 3 робочих дні (`workingDaysBetween`, той самий, що в паймент-матчі). Поріг у константі, не в БД.
9. Прогрес **не скидається** при зміні ролі; при видаленні матеріалу рядки прогресу зникають каскадом, відсоток перераховується.
10. Редагування курсу з наявним прогресом: додавання уроку знижує відсотки всім, і це правильно (курс став довшим). Про це попереджає редактор.

## 6. API

Усі під `/api/training`, у матриці доступу (`accessMatrix.ts`) з `ROUTE_TAB = training`; запис — через `requirePerm('manage_training')`.

| метод | шлях | хто | що |
|---|---|---|---|
| GET | `/courses` | усі з вкладкою | курси за аудиторією ролі + мій відсоток по кожному |
| GET | `/courses/:id` | усі | блоки, матеріали, для кожного `state: locked/available/opened/done`, `blockedBy` |
| POST | `/progress/:materialId/open` | усі | фіксує відкриття; 423, якщо locked |
| POST | `/progress/:materialId/done` | усі | урок → done; для quiz заборонено (400) |
| POST | `/quiz/:materialId/submit` | усі | тіло `{answers}` → `{score, passed, attemptsLeft, perQuestion}`; 423 якщо locked або спроби вичерпано |
| GET | `/overview` | тімлід (своя команда), КВП/опдир/СЕО/адмін | зведення: люди × курси |
| GET | `/overview/:userId` | ті самі | детально: кроки, бали, відповіді на `text`, події |
| POST | `/overview/:userId/unlock-exam` | адмін, опдир, тімлід своєї команди | +1 спроба екзамену, подія |
| POST | `/courses`, PATCH `/courses/:id`, DELETE | `manage_training` | CRUD курсу |
| PATCH | `/folder/:id` (є) | `manage_training` | + `course_id` |
| POST/PATCH | `/material` (є) | `manage_training` | + `quiz_json`, `is_exam`, `required`; валідація zod: у quiz ≥ 1 автоматичне питання, `correct` у межах `options` |
| POST | `/hire/:userId` | адмін, опдир, СЕО | `{teamId}` → `role_override='manager'`, `team_id`, подія `hired`, запис у журнал ролей |

`onlyAdmin` у `routes/training.ts` замінюється на `requirePerm('manage_training')`; адмін має право за замовчуванням, тож поведінка для нього не змінюється.

## 7. Екрани

### 7.1 Учень (кандидат, менеджер)
- **Список курсів**: картка з назвою, описом, шкалою 0–100 %, підписом «зараховано ✓» або «крок N із M». Для кандидата це вся вкладка, нічого більше.
- **Курс**: блоки як розділи; у кожному уроки й тести списком. Стани: `done` ✓ зелений; `available` звичайний; `locked` сірий, без кліку, з підписом «спершу пройди: <назва>». Екзамен окремим блоком у кінці з підписом «відкриється при 100 %».
- **Урок**: PDF і зображення відкриваються в дашборді (PDF через `<iframe>` на файл-роут, зображення напряму); відео як embed; файли DOCX/XLSX на завантаження (як у ТЗ документів, конвертацію не робимо). Кнопка «Пройшов, далі →» веде на наступний доступний.
- **Тест**: питання по одному або всі на сторінці (макет Юлі вирішує), «Здати» → результат: бал, прохідний, по кожному питанню правильно/ні (без показу правильної відповіді для екзамену). «Спробувати ще» доки є спроби.
- **Мобільний**: кандидати часто з телефону, тож шкала, список і тест мусять працювати на 375 px без горизонтального скролу.

### 7.2 Керівник
- **Зведення**: таблиця людина × курс: відсоток, поточний крок, бал екзамену, остання активність, бейдж «застряг». Фільтри: команда (тімліду лише своя), роль (кандидати/менеджери), курс. Сортування за відсотком і за давністю активності.
- **Картка людини**: список кроків з датами, спроби тестів з балами, відповіді на вільні питання, кнопки «Відкрити ще спробу екзамену» і **«Прийняти на роботу»** (лише для кандидата; адмін, опдир, СЕО): модалка з вибором команди → підтвердження → людина стає менеджером; на картці лишається подія з датою й автором.

### 7.3 Редактор (право `manage_training`)
- Курси: створити, назва, опис, аудиторія, послідовність увімк/вимк, опублікувати.
- Блоки: наявні папки з привʼязкою до курсу, порядок стрілками.
- Матеріали: наявна форма + тип «Тест» з конструктором: питання, тип, варіанти, правильні, прохідний бал, спроби; перемикач «Екзамен» (лише один на курс, автоматично останній); «Обовʼязковий».
- Попередження при додаванні матеріалу в курс, який уже хтось проходить: «відсотки N людей знизяться».

## 8. Гейти — з умовою червоніння

| # | твердження | червоніє, якщо |
|---|---|---|
| A | при `sequential=true` матеріал 2 locked, поки 1 не done (чиста функція `materialState`) | прибрати перевірку порядку |
| A🪞 | після done 1 матеріал 2 available; при `sequential=false` усе available одразу | зламати перехід або ігнорувати прапорець |
| B | відсоток курсу == done ÷ required, фікстура: 2 блоки, 5 матеріалів, 1 необовʼязковий → 3 із 4 = 75 % | змінити знаменник або врахувати необовʼязковий |
| C | роль `candidate` відповідає 403 на кожен роут поза `training` (перебір `ROUTE_TAB`) і 200 на `GET /training/courses` | дати роль з іншим екраном; дзеркало ловить «403 усюди» |
| D | екзамен locked при 99 %, available при 100 % решти | зняти умову |
| D2 | 4-та спроба екзамену → 423; після `unlock-exam` → дозволена | прибрати ліміт або зробити unlock холостим |
| E | `/overview` тімліду віддає лише свою команду; адміну всіх; менеджеру 403 | розширити скоуп |
| F | після бекфілу `COUNT(*) FROM training_folders WHERE course_id IS NULL = 0` (живий, `needsBackendEnv`) | пропустити папку |
| G | `POST /hire` міняє `role_override` і `team_id` і пише подію; для не-кандидата 400 | пропустити подію або дозволити на менеджері |
| H | бал тесту рахується лише по автоматичних питаннях, `text` не впливає | врахувати `text` |

## 9. Що може зламатись — поіменно
- **`#15`/`#15b`** на прийманні викату: нова роль без оголошення. Закривається кроком 1.
- **Матриця `#17`**: 11 нових/змінених роутів, кожен у `accessMatrix.ts` з межею.
- **Наявні матеріали** мусять лишитись видимими всім, у кого вкладка є: бекфіл у курс «Загальне навчання» з `sequential=false`, гейт F.
- **Налаштування → користувачі**: список показує `role_effective`; нова роль має бути у випадачці, інакше Даша не заведе кандидата.
- **Новини за ролями** (задача 27): кандидат не має бачити новини про викати. Роль без вкладки `news` це вирішує само.
- **Календар відсутностей** уже підтримує акаунти без менеджера (викат 09.09), тож кандидат там не зламає нічого.

## 10. Відкриті питання Сергію (потрібні до кроку 2)
1. **Послідовність для менеджерів**: блокує чи лише показує? Пропоную: кандидатам блокує, менеджерам показує.
2. **Спроби екзамену**: пропоную 3, наступну відкриває керівник.
3. **«Автоматичне» навчання по дашборду** (08.09): що саме мається на увазі? Пропоную: звичайний курс «Дашборд», який ми доповнюємо при кожному викаті з помітними змінами, руками.
4. **Хто редагує матеріали**: Даша, Юля? Тоді їм право `manage_training`.
5. **Підпис оффера**: Дія (13.09) чи код у Telegram (рішення 10.09)? Не в цьому ТЗ, але впливає на крок «Прийняти»: чи чекати підпису перед зміною ролі. Пропоную: не чекати (рішення ③ у ТЗ документів: непідписаний оффер нічого не блокує).

## 11. Чого не робимо
1. Підпис оффера, документи — окреме ТЗ.
2. Автостворення акаунта в CRM і Google-пошти — після переходу на Twenty; під Kommo не будуємо.
3. Перенос матеріалів і тестів із «Середи» кодом — це роблять люди в редакторі після зустрічі з Іваном; ми даємо інструмент.
4. Конвертацію DOCX/XLSX у PDF — як у ТЗ документів, за результатом заміру.
5. Відстеження відсотка перегляду відео.
6. Сертифікати, бейджі, гейміфікацію.
