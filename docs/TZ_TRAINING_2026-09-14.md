## 1. Мета

Дашборд стає єдиним місцем навчання замість «Середи». Кандидат отримує акаунт з роллю «Кандидат» і бачить лише вкладку «Навчання». Курс складається з модулів, модулі з уроків і тестів. Усі модулі видно одразу, але наступний закритий замком, поки не пройдено попередній. Курс зараховано при 100 % і складеному екзамені. Керівник бачить зведення: хто на якому кроці, з якими балами, хто застряг. Після рішення про найм керівник однією дією обирає команду, і кандидат стає менеджером.

## 4. Ролі й доступ

| роль | бачить | може |
|---|---|---|
| **Кандидат** (`candidate`, нова) | лише курси з аудиторією `candidate`; жодної іншої вкладки | проходити уроки й тести |
| Менеджер | курси `manager` і `all` | проходити, з тими самими замками |
| Тімлід | те саме + зведення по своїй команді | дивитися прогрес своїх; відкривати спробу екзамену своїм |
| КВП, опдир, СЕО, адмін | усі курси + зведення по всіх | адмін, опдир, СЕО: «Прийняти на роботу» |
| `manage_training` (право) | — | редагувати курси, модулі, матеріали, тести |

Технічно: роль `candidate` — рядок у `ROLE_DECLARATIONS` + сід у `roles` (`screen_access={training:true}`, `permissions={}`, `data_scope='own'`, `manager_id=NULL`). Право `manage_training` — у `permissions` ролі `admin` за замовчуванням; `onlyAdmin` у роутах навчання замінюється на `requirePerm('manage_training')`.

## 5. Модель даних

### 5.1 Нові таблиці

```
training_courses
  id, title, description, audience CHECK IN ('candidate','manager','all'),
  position, published, created_by, created_at

training_progress
  id, user_id → users, material_id → training_materials (CASCADE),
  status CHECK IN ('opened','done'), score NUMERIC, passed BOOLEAN,
  attempts INT DEFAULT 0, answers_json JSONB, opened_at, finished_at,
  UNIQUE (user_id, material_id)

training_events
  id, user_id, material_id, kind CHECK IN ('open','done','quiz_attempt','exam_unlock','course_done','hired'),
  payload_json, at
```

### 5.2 Зміни наявних таблиць (лише додавання)

```
training_folders    + course_id → training_courses        (папка = модуль курсу)
training_materials  + kind дозволяє 'quiz'
                    + quiz_json JSONB
                    + is_exam BOOLEAN DEFAULT false
                    + required BOOLEAN DEFAULT true       (необовʼязковий не входить у 100 %)
```

### 5.3 Форма тесту `quiz_json`

```json
{
  "pass_score": 80,
  "max_attempts": null,
  "shuffle": true,
  "questions": [
    { "id": "q1", "text": "…", "kind": "single", "options": ["…","…","…"], "correct": [1] },
    { "id": "q2", "text": "…", "kind": "multi",  "options": ["…","…"],     "correct": [0,1] },
    { "id": "q3", "text": "…", "kind": "text",   "correct": null }
  ]
}
```
`single`/`multi` перевіряються автоматично; `text` не рахується в бал, зберігається для керівника. Бал = правильні ÷ автоматичні × 100, ціле. Для екзамену `max_attempts = 1`.

### 5.4 Бекфіл (один прохід, оборотний)
1. Курс «Загальне навчання» (`audience='all'`); усі наявні папки отримують його `course_id`.
2. Усім, хто на момент викату має роль менеджера, тімліда чи вище, наявні матеріали позначаються `done`: інакше замки закриють людям те, що вони вже читали.
3. Гейт F перевіряє, що папок без курсу нуль.

## 6. Правила прогресу

1. Одиниця прогресу — матеріал із `required=true` (урок або тест).
2. Урок done: натиснуто «Пройшов, далі» після відкриття.
3. Тест done: `passed=true`, тобто `score ≥ pass_score`.
4. Відсоток курсу = done ÷ усіх required × 100, ціле. Екзамен у знаменнику.
5. Доступність: матеріал доступний, коли всі попередні за порядком (модуль за `position`, усередині модуля матеріал за `position`) done. Інакше `423 Locked` з `{blockedBy: {materialId, title}}`. Закриті елементи **віддаються у списку**, не ховаються.
6. Екзамен (`is_exam`) доступний при done усіх інших required; завжди останній за побудовою; 1 спроба; наступну відкриває керівник.
7. Курс зараховано = 100 % і екзамен passed; подія `course_done`.
8. Застряг = курс не зараховано і немає подій ≥ 3 робочі дні (`workingDaysBetween`). Поріг у константі.
9. Прогрес не скидається при зміні ролі. Видалення матеріалу каскадно прибирає прогрес, відсоток перераховується.
10. Додавання матеріалу в курс, який хтось проходить, знижує їм відсоток; редактор попереджає.

## 7. API

Усі роути під `/api/training`, у матриці доступу з `ROUTE_TAB = training`; запис — `requirePerm('manage_training')`.

| метод | шлях | хто | що |
|---|---|---|---|
| GET | `/courses` | усі з вкладкою | курси за аудиторією + мій відсоток і поточний крок |
| GET | `/courses/:id` | усі | модулі й матеріали зі `state: locked/available/opened/done`, `blockedBy` |
| POST | `/progress/:materialId/open` | усі | фіксує відкриття; 423 якщо locked |
| POST | `/progress/:materialId/done` | усі | урок → done; для quiz 400 |
| POST | `/quiz/:materialId/submit` | усі | `{answers}` → `{score, passed, attemptsLeft, perQuestion}`; 423 якщо locked або спроби вичерпано |
| GET | `/overview` | тімлід (своя команда), КВП, опдир, СЕО, адмін | зведення люди × курси |
| GET | `/overview/:userId` | ті самі | кроки, бали, відповіді на `text`, події |
| POST | `/overview/:userId/unlock-exam` | адмін, опдир, тімлід своєї команди | +1 спроба, подія `exam_unlock` |
| POST/PATCH/DELETE | `/courses`, `/courses/:id` | `manage_training` | CRUD курсу |
| PATCH | `/folder/:id` | `manage_training` | + `course_id` |
| POST/PATCH | `/material` | `manage_training` | + `quiz_json`, `is_exam`, `required`; валідація: ≥ 1 автоматичне питання, `correct` у межах `options`, не більше одного екзамену на курс |
| POST | `/hire/:userId` | адмін, опдир, СЕО | `{teamId}` → `role_override='manager'`, `team_id`, подія `hired`; для не-кандидата 400 |

## 8. Екрани

### 8.1 Учень (кандидат, менеджер)
- **Список курсів і модулів**: усі видно одразу. Картка модуля: «Модуль N», назва, опис, шкала 0–100 %, кнопка праворуч: «Продовжити» у доступного, «🔒 Відкриється після: <назва>» у закритого (неактивна). Картка розгортається стрілкою в список уроків і тестів. Оформлення — токени дашборда, не копія Mate.
- **Урок**: PDF і зображення відкриваються в дашборді, відео як embed, DOCX/XLSX на завантаження. Кнопка «Пройшов, далі →».
- **Тест**: питання, «Здати», результат одразу: бал, прохідний, по кожному питанню правильно чи ні (для екзамену без показу правильної відповіді). «Спробувати ще», якщо є спроби; для екзамену після невдачі підпис «звернись до керівника».
- **Мобільний**: 375 px без горизонтального скролу.

### 8.2 Керівник
- **Зведення**: таблиця людина × курс: відсоток, поточний крок, бал екзамену, остання активність, бейдж «застряг». Фільтри: команда (тімліду лише своя), роль, курс. Сортування за відсотком і давністю.
- **Картка людини**: кроки з датами, спроби тестів з балами, відповіді на вільні питання, кнопки «Відкрити спробу екзамену» і «Прийняти на роботу» (лише для кандидата): модалка з вибором команди → підтвердження → людина стає менеджером; подія лишається в картці з датою й автором.

### 8.3 Редактор (`manage_training`)
- Курси: створити, назва, опис, аудиторія, опублікувати.
- Модулі: наявні папки з привʼязкою до курсу, порядок стрілками.
- Матеріали: наявна форма + тип «Тест» з конструктором (питання, тип, варіанти, правильні, прохідний бал), перемикач «Екзамен» (один на курс, автоматично останній), «Обовʼязковий».
- Попередження при додаванні матеріалу в курс із наявним прогресом.

## 10. Що може зламатись — поіменно
- `#15`/`#15b` на прийманні: нова роль без оголошення. Закриває крок 1.
- Матриця `#17`: 12 нових або змінених роутів, кожен з межею.
- Наявні матеріали: бекфіл у курс «Загальне навчання» + `done` наявним, гейт F.
- Налаштування → користувачі: роль «Кандидат» у випадачці, інакше Даша не заведе акаунт.
- Новини за ролями: кандидат без вкладки `news` їх не бачить, окремої правки не треба.
- Календар відсутностей уже працює з акаунтами без менеджера (викат 09.09).
