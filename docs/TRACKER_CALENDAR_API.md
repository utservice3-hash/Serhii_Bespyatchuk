# Календар команди для тайм-трекера — контракт (04.11.2026)

Трекер сам питає дашборд про відсутності, чергування й свята. Дашборд — єдине джерело («Календар команди»),
трекер лише читає. Наступник `GET /api/integrations/tracker/vacations` ([TRACKER_VACATIONS_API.md](TRACKER_VACATIONS_API.md)),
який поки лишається: прибрати його можна, коли трекер скаже, що перейшов.
Код: `backend/src/routes/integrations.ts`, правила — `backend/src/core/trackerCalendar.ts`,
гейти `#3352`/`#3352b` (`backend/src/routes/integrations.test.ts`).

## Запит

```
GET https://dashboard.uts.ua/api/integrations/tracker/calendar?from=2026-10-01&to=2026-10-31
X-Tracker-Vacations-Key: <той самий ключ, що й для vacations>
```

- Ходить **лише сервер трекера**; ключ живе тільки на сервері, лише на читання, окремий від SSO.
- `from`, `to` — `YYYY-MM-DD`, обидва дні включно, `from ≤ to`, період не довший за 366 днів.

## Відповідь `200`

Фікстура: [tracker-calendar.example.json](tracker-calendar.example.json). Це саме та відповідь, яку гейт `#3352`
отримує від роуту на тестовій базі, а `#3352b` звіряє з нею байт у байт — розійдеться з кодом, гейт почервоніє.
У ній є всі чотири `kind`, усі три `shift`, обидва `status`, звільнений (`active: false`) і відпустка через межу періоду.

### `absences` — відсутності

| поле | значення |
|---|---|
| `id` | id запису в календарі |
| `dashboardUserId` | id акаунта, той самий, що в `GET /api/auth/tracker-users`; `email` — запасний ключ, нижній регістр |
| `kind` | `vacation` · `sick` · `day_off` · `short_day` |
| `status` | `approved` або `pending`. Рахувати — лише `approved`; `pending` — «очікує погодження». `rejected` не віддається |
| `from`, `until` | календарні дати (київський день), обидва включно; **не обрізані** по `from`/`to` запиту. Поденні (`day_off`, `short_day`): `until = from` |
| `hours` | лише `short_day`: **на скільки годин день коротший** (у календарі — «скороч. −N год»). Для решти — `null`. З котрої до котрої людина працює, не зберігається |
| `active` | `false` — акаунт вимкнений (звільнений); запис віддається, щоб минулі звіти лишились правильними |

Погоджують і заднім числом: статус може змінитися вже після дати. Порядок — за `from`, далі за `id`.

### `duty` — чергування

| поле | значення |
|---|---|
| `id`, `dashboardUserId`, `email`, `active` | як у `absences` |
| `date` | день чергування |
| `shift` | як у базі: `day` («Весь день»), `evening` («Вечір 18–21»), `weekend` |
| `until` | `"21:00"` для `evening`, `null` для решти |

⚠️ На суботу й неділю чергових ставлять здебільшого зміною `day`, а не `weekend` (заміряно 04.11.2026: 82 проти 1).
Запис на вихідний чи свято відкриває **будь-яке** чергування того дня. В однієї людини в один день можуть бути
і різні зміни, і відсутність разом із чергуванням. Порядок — за `date`, далі за `id`.

### `holidays` — свята

`{ "date": "YYYY-MM-DD", "name": "..." }` — одні на всю компанію; вносить адмін вручну.

### Хто не потрапляє

Записи людей без акаунта в дашборді (у трекері таких немає) і все, що не перетинає період.
Нема записів — порожні масиви.

## Помилки

| код | тіло | коли |
|---|---|---|
| `400` | `{ "error": "<причина>" }` | дати не `YYYY-MM-DD` / неіснуючі, `from` пізніше `to`, період > 366 днів |
| `401` | `{ "error": "bad_key" }` | ключа немає або він не той (зокрема SSO-ключ) |
| `503` | `{ "error": "not_configured" }` | на дашборді не налаштовано `TRACKER_VACATIONS_KEY` |
