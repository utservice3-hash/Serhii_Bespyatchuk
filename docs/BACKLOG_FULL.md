## 🎯 КРОК 7 — ПЛАНИ / СКОРКАРД ВІДДІЛІВ

### Скоркард лідогена
План/факт по кожному менеджеру лідогена: успішні дзвінки · цільові/нові ліди · контакти ОПР ·
передано на прорахунок · поставлені машини · сума очікування · сума з поставлених. Ціль — гроші.

### Динамічний план менеджера продажів
Тімлід ставить місячний план (авто/грн). Щоночі перерахунок денної норми = (план − факт) /
робочі дні, що лишились, коридор 50–150%. Конверсія й сер. чек виводять, скільки треба лідів/дзвінків.
Реактивація: продзвін/реактивація мають свою когортну конверсію (вже готова).

## 🧊 ЗАМОРОЖЕНІ ФІЧІ

### Реактивація — стадія «Відправлено у відділ продажів»
Власник повертає команді реактивації правило вести стадію (покинули з 04.2026, ловить вартовий 6.6).
Handoff-конверсія оживе автоматично — метрика вже готова (`conversion_reactivation_handoff`).

### Календар чергувань
Чергування у вихідні, ціль ≥8 лідів/день (авто з CRM). Відчергував + ≥8 → 1 відгул у будній.
Відгул обирає менеджер, тімлід затверджує, баланс ≥0. Календар рівня Google: лікарняні/відпустки/свята.
Права: менеджер — свої + чергування команди; тімлід — команда; адмін — усе.

### Ван-ту-ван
Покроковий вигляд, автозбереження чернетки. Два набори (Адмін↔Тімлід, Тімлід↔Менеджер).
Останнє питання — оцінка 1–10. Поруч — відповідь з минулого місяця. Шаблони в БД. Квартальні — 1-й міс кварталу.

### Автозадача «Провести 1-на-1»
1-го числа авто-створення задач: тімліду — з менеджерами, операційному — з тімлідами. Ідемпотентно.

### Фільтр по командах у задачнику
Дворівневий фільтр: команди + менеджери, множинний вибір, стан у URL.

### Час опрацювання — розширення UI
Медіана + p90 + гістограма, історія тренду, розріз по менеджерах/командах/джерелах, дрилдаун у Kommo.

### Статистики (відділи) — дороблення
Розділ depstats. Фінанси/HR/Маркетинг — ручний ввід через форму (замість Google-таблиці).

### 💰 ГРОШІ — ДВА РІЗНІ ДЖЕРЕЛА
| Метрика | Джерело | Стан |
|---|---|---|
| **Сума очікування** (цей/наст. місяць) | поле «Запланована дата оплати» в Kommo | ✅ ЗРОБЛЕНО (Р2) |
| **Дебіторка** (тотал) | ручна гугл-таблиця (безнал) | ✅ вирівняно 1:1 (17.07) |
| **Реальна дебіторка** (факт оплат) | **API банків + 1С** | ⏳ ВІДКЛАДЕНО (великий блок) |

**⏳ ВІДКЛАДЕНО — реальна дебіторка:**
- **Б1.** Оплати не підтягуються (Антипенко: 5 оплат → нуль). Причина — ручна таблиця відстає.
- **Б2.** Дебіторка = факт оплат некоректний. Та сама причина.
- Рішення: прибрати Google-таблицю, підключити API банків + 1С → факт оплат авто. (1С — найскладніше.)

**Б3. KPI по клієнтах: збереження ГУБИТЬ дані (Яцик).** Два показники + зберегти → злітають.
+ UX: одна кнопка на всю таблицю замість кнопки на клієнта. → `RepeatClientPlans`. Спершу баг, потім one-button.

### 🎨 UX / фічі
- **Ф-к0. Застряглі угоди від лідогена (Яцик).** >2 днів без руху/контакту → окремо в «Огляд → Застряглі»,
  позначати (1) від лідогена, (2) днів без руху. → розширення `/stuck-deals` + звʼязок із задачником.
- **Ф-к1. Шкала виконання плану по менеджеру (Яцик).** 100% зелений (успіх), жовтий (очікування),
  червоний/білий (залишок). → **збігається зі світлофором звіту КВП** (Р4c).
- **Ф-к2. Місячні плани — окремий розділ + аналіз (Яцик).** → **КРОК 7**.
- **Ф-к3. План спамить задачник (Яцик).** Дні засмічують. Місяць→тижні→дні у випадаючий список.
  → перевірити «задача-парасолька + приховані діти-дні» (могло регресувати / потребує UI-згортання).
- **Ф-к4. AI-бот повертає ВСІ угоди в реактивацію (Михальчевська).** Не повертати: разові, не актуальні,
  без звʼязку (3 дзвінки/день), дешеві по місту. → критерії-виключення в `reactivateLeads` (уточнити з власником).
- **Ф-к5. Регламент роботи з дашбордом (Яцик).** → навчання/інструкція (не код).
