# Serhii_Bespyatchuk

Веб-дешборд компанії з даними з Kommo CRM (заміна ручних звітів у Google Таблицях).

## Структура

- `backend/` — Node.js/TypeScript/Express API, синхронізація з Kommo CRM, PostgreSQL
- `frontend/` — React/TypeScript/Vite дешборд з графіками (Recharts)

## Запуск backend

```bash
cd backend
cp .env.example .env   # заповнити DATABASE_URL, JWT_SECRET, KOMMO_API_TOKEN
npm install
npm run migrate         # створити таблиці
npm run sync:users       # швидка синхронізація лише користувачів Kommo (заповнює managers)
npm run migrate:mapping  # прив'язати менеджерів до команд + маппінг етапів воронки
npm run sync             # повна синхронізація угод (інкрементально, дивись нижче)
SEED_ADMIN_PASSWORD=... npm run db:seed  # перший admin-користувач (опційно)
npm run dev
```

### Синхронізація угод (`npm run sync`)

Синхронізація інкрементальна: зберігає час останнього запуску в таблиці
`sync_state` і при наступних запусках запитує в Kommo лише угоди, що
змінились після цього часу (`filter[updated_at][from]`). Перший запуск
(коли `sync_state` порожня) обмежений останніми 180 днями, щоб уникнути
непередбачуваного імпорту всієї багаторічної історії акаунта. Сторінки
з Kommo та upsert-и в БД виконуються пакетно паралельно для прискорення
на великих обсягах даних.

Рекомендується запускати `npm run sync` періодично через cron/планувальник
(або виклик `/sync` в Telegram-боті, дивись нижче).

## Що зроблено

- Аутентифікація через JWT з ролями `admin` / `team_lead` / `manager`
- Синхронізація лідів/угод і користувачів з Kommo CRM (cron кожні 15 хв)
- Маппінг команд та воронок Kommo (`src/db/seedKommoMapping.sql`):
  - **РНК / РПК / Тендери** — спільна воронка `Перевозки (Продажі повний цикл) (New)`
    (id `8921932`), команди розрізняються за відповідальним менеджером
  - **Лідогенератори** — воронка `Продзвін (New)` (id `8921936`)
  - Команди: Михальчевська, Безпамятний → РНК; Шаврова, Дмитрук → РПК;
    Ковтонюк, Сердюк → Лідогенератори; Шевчук, Дяков → Тендери (тім-лід Яцик)
  - **КВП** (керівник відділу продажу) — не команда з угодами, а роль:
    користувач з роллю `admin` бачить агреговану статистику по всій компанії
    без фільтрів за командою/менеджером
  - Етапи воронки: `lead_taken` (взято на прорахунок) → `quote_requested`
    (пропозицію зроблено) → `approved` (умови узгоджені) → `invoiced`
    (рахунок виставлено) → `paid` (оплата отримана)
- Ручне введення планових показників (`/api/plans`)
- Дешборд воронки продажів: графік по етапах + динаміка по днях/місяцях
  (`/api/dashboard/timeseries`) з фільтром по команді

## Створення користувачів

```bash
# Керівник відділу продажу (КВП) — повний огляд по всій компанії
npm run create-user -- --email=head@company.com --role=admin

# Тім-лід команди — бачить тільки свою команду
npm run create-user -- --email=yatsyk@company.com --role=team_lead --team="Тендери"
```

Якщо `--password` не вказати, згенерується випадковий пароль і буде показаний
один раз у консолі — його варто одразу передати користувачу.

## Telegram-бот для адмінів

Підтримка та керування користувачами (без доступу до сервера) — через
Telegram-бота на базі `grammy`. Доступ лише для адмінів зі списку
`TELEGRAM_ADMIN_IDS`.

```bash
# .env: TELEGRAM_BOT_TOKEN, TELEGRAM_ADMIN_IDS (Telegram user id через кому)
npm run bot
```

Команди бота:

- `/teams` — список команд
- `/users` — список користувачів дешборду
- `/adduser email role [team]` — створити/оновити користувача,
  бот відповість логіном і згенерованим паролем
  (`role`: `admin` | `team_lead` | `manager`)
- `/sync` — запустити синхронізацію з Kommo вручну
