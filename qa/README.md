# E2E Smoke-QA — перевірка дашборду «перед кожним показом»

`qa/smoke-qa.mjs` — Playwright-харнес, що **лише знаходить**, нічого не чинить.
Ганяється однією командою, фейл → скрін. Задум — як нічна звірка: прогнати перед
кожним показом/деплоєм.

## Що перевіряє

**1. Механіка** — усі роути (Огляд / Звіт / Звіт 2.0), рівні (Відділ/Команда/Менеджер),
періоди (Місяць/Тиждень), світлофор, перемикачі, dropdown-и. Фейл, якщо:
помилка в консолі · ErrorBoundary «Не вдалося показати» · dropdown 0 опцій ·
«NaN»/порожнє в DOM.

**2. Інваріанти** (на даних `/manager-report`): Σ менеджерів = Σ команд = відділ
(факт/план); сума бакетів очікувань = total; конверсія ≤100%.

**3. Крос-екран** (аудит Огляду): спільні метрики (факт · прогноз · очікування)
«Огляд» vs «Звіт 2.0» мають збігатися. Розбіжність = FAIL + два скріни + яка формула стара.

Вивід: `qa-out/report.json` (PASS/FAIL + деталі) + скріни падінь. Exit code 1 при будь-якому FAIL.

## Запуск

**LIVE (рекомендовано, власник — з машини з доступом до прод):**
```
QA_TOKEN=<admin-jwt> node qa/smoke-qa.mjs
# опційно: QA_BASE_URL=https://dashboard.uts.ua  QA_OUT=./qa-out  QA_CHROMIUM=<chrome>
```
admin-jwt генерується так само, як у діагностиці (`signToken({userId,role:'admin',...})`).

**OFFLINE (фікстури, без доступу до прод):**
```
QA_FIXTURES=<dir з overview.json,mr_dept.json,teamsapi.json> \
QA_DIST=<frontend/dist>  QA_TOKEN=<admin-jwt>  node qa/smoke-qa.mjs
```
⚠️ OFFLINE надійно перевіряє лише **дані** (інваріанти + крос-екран) і Звіт 2.0 в ізоляції;
повна **механіка Огляду/старого Звіту** потребує LIVE (offline-моки неповні — інші
ендпоінти віддають `[]`, тож ці екрани падають у ErrorBoundary штучно).

## Залежності
`playwright-core` + встановлений Chromium (`QA_CHROMIUM`, дефолт `/opt/pw-browsers/...`).
Не додано в package.json навмисно (QA-only tool; ставити локально `npm i playwright-core`).
