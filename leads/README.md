# Импорт лидов N5Deal — разбор отказа и починка

## Что произошло

Файл `n5deal_leads_batch1.csv` платформа не приняла. Причина не в синтаксисе CSV:
файл разбирается корректно — 133 строки × 9 полей, кавычки и экранирование в порядке.
Отказ вызван содержимым полей.

## Аудит исходного файла (132 строки данных)

| Поле | Проблема | Строк |
|---|---|---|
| `company` | **пусто** | **101 из 132 (77%)** |
| `comments` | длиннее 255 символов (макс. 454) | **114** |
| `comments` | кириллица и длинное тире `—` | 119 |
| `resource` | пусто во всех строках | 132 |
| `email` | пусто | 131 |
| `phone` | пусто | 130 |
| `contact_persons` | пусто | 0 |
| дубликаты по имени | нет | 0 |

Главный подозреваемый — пустой `company` в 77% строк: это первая колонка формы и
почти всегда обязательное поле в CRM. Второй — переполнение `comments` при
типичном лимите `varchar(255)`.

## Что исправлено

1. **`company` заполнена во всех 131 строке.**
   - 31 — значение из исходного файла;
   - 100 — независимые советники без работодателя в заголовке, компанией записано имя человека.

   Автоматическое извлечение работодателя из заголовка профиля отключено: на этих
   данных оно давало ложные срабатывания вида «Head of Legal» → компания «Legal».
2. **`comments` сокращены до ≤ 200 символов** (было до 454) и переписаны структурно:
   `[Трек] | Локация | owner | LinkedIn 28.08.2026 | NOT SENT | заголовок профиля`.
3. **Только ASCII.** Кириллица и `—` убраны из импортируемых файлов.
   Пять строк, где текст был полностью русским (Ryan Morgan, Julian Liniger,
   Peter Cox, Mariusz Malec, Igor Chukhray), переписаны на английский вручную —
   автоматическая вычистка оставляла от них мусор.
4. **Loukas Lagoudis удалён** — дублирует лид, заведённый руками.
5. Формат: RFC4180, все поля в кавычках, ровно 9 колонок в каждой строке, CRLF.

Полный русский контекст (зацепки, исходные заголовки, статусы) не потерян —
он лежит в `import/n5deal_leads_v2_reference.csv`. Этот файл **не для импорта**,
он рабочий: из него пишутся записки.

## Что осталось непроверенным

`type` во всех строках — `partner` (значение из исходного файла). В платформе у
существующих лидов тип отображается как `Partner (I…)`. Если поле — строгий
справочник, `partner` может не пройти. Проверить это без доступа к платформе
нельзя: нужно либо точное значение из карточки существующего лида, либо текст
ошибки импорта.
