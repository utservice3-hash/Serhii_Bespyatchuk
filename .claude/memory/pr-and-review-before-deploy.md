Власник 05.10.2026: «З наступного проходу оформлюй PR і чекай мого огляду до викату». Раніше ланцюг деплою пушив задеплоєну версію в `main` без PR — власник прийняв це пояснення, але далі хоче бачити зміни до того, як вони підуть на прод.

**Why:** власник хоче оглядати код до проду, а не постфактум по комітах.
**How to apply:** гілка → push → PR (у цьому середовищі `gh` немає — давати посилання `…/pull/new/<гілка>` або compare) → СТОП до «ок» на огляд → лише тоді deploy:check/run. Див. [[merge-and-deploy-need-explicit-approval]], [[no-direct-push-to-main]].

⚠️ **05.10.2026 увечері, той самий день:** на PR для прибирання задач (feat/carrier-stage-task-sweep) Роман відповів «ні викочуй все, який пр, зробив — викат». Тобто правило не абсолютне: коли власник прямо каже «викочуй», PR не чекаємо. Якщо незрозуміло, чи потрібен PR на наступний прохід, коротко спитати разом зі звітом, а не зупинятись.
